# TIM Core 1.0 — Freeze Declaration

**Status:** FROZEN  
**Operating mode:** OBSERVE-only  
**Purpose:** Deterministic market research  

This document freezes the currently implemented research core. It does not
change runtime behaviour, market rules, thresholds, or validation logic. The
machine-readable source of truth is `config/core_manifest.json`.

## Frozen component set

| Component | Version |
|---|---:|
| AggTrade Persistence | 1.0.0 |
| Orderflow Metrics | 1.0.0 |
| Orderflow Observations | 1.0.0 |
| Orderflow Validation | 1.0.0 |
| Research Analytics | 1.0.0 |
| Dashboard | 4.1.0 (see addenda 2026-09-28) |

The dashboard is recorded as `2.1.0` because this is the version declared by
the running implementation at freeze time. Re-labelling it as `2.0.0` would
make the frozen manifest inconsistent with the software being observed.

## Change policy

Allowed changes are limited to:

- fixes for reproducible defects;
- integrity and security corrections;
- documentation and monitoring;
- scientific methodology that does not alter runtime results.

The following are prohibited in Core 1.0:

- new observation rules or data sources;
- threshold changes;
- changes to outcome definitions or validation logic;
- any other functional extension of the research core.

Any necessary functional change requires a new Core version. Data generated by
different Core, rule, metric, or validation versions must never be silently
combined in one analysis.

## Phase 5 release gate

Phase 5 remains locked until recorded evidence demonstrates all of the
following:

1. Sufficient real runtime and documented data coverage.
2. A sufficient number of fully validated orderflow cases.
3. Stable deterministic replay results.
4. Version consistency across the evaluated dataset.
5. No unresolved integrity issue.

There is no automatic unlock. A release decision must cite persisted evidence
and define the next Core version before development resumes.

## Scientific operating principle

TIM Core 1.0 now advances through the quality, coverage, and reproducibility of
observed data—not through additional features. It remains read-only and does
not create orders, trading signals, or execution paths.

## Addendum 2026-09-28: Dashboard 3.0.0

**Decision by the owner (2026-09-28):** the dashboard component is released
from the freeze for a full redesign as version `3.0.0`. Scope of the release:
presentation, navigation, code structure of `src/dashboard/`, a verifiable
case export route, a read-only orderflow history API, a retrospective view on
case detail and a local-only pilot view.

Unchanged and still frozen: `core_version` 1.0.0, observation rules, thresholds,
metrics, orderflow validation logic, outcome definitions, persistence and all
research data. The dashboard stays OBSERVE-only and read-only; no order,
signal or execution path is added. Existing `/api/*` contracts stay compatible.

Version history note: the running code declared `DASHBOARD_VERSION = "2.2.1"`
while this manifest still recorded `2.1.0`, i.e. the dashboard had already
been changed after the freeze without a manifest update. Both now read `3.0.0`.
Because `config/core_manifest.json` changed, research snapshots created after
this date carry a different `core_manifest_hash`; research data itself is not
affected and needs no re-analysis.

## Addendum 2026-09-28: Dashboard 4.1.0 (Zusammenführung)

**Decision by the owner (2026-09-28):** the live runtime (branch
`opencode/rolling-liveness-ops-fix`, PR #87, plus the previously uncommitted
live state saved as `opencode/live-snapshot-2026-09-28`) and `platform-main`
are merged. The live runtime already declared `DASHBOARD_VERSION = "4.0.0"`
("Control Center") while its manifest still recorded `2.1.0`; `platform-main`
recorded `3.0.0`. The merged dashboard is `4.1.0`: the Control Center layout
and all its pages, APIs and security layer (loopback-only bind, Host check,
security headers, response size limit, hash-based CSP) plus the Dashboard 3.0
additions (German labels, lifecycle badges, case proof export, orderflow
history API, retrospective, local pilot view). The CSP is now computed per HTML
response from the inline blocks it contains; `unsafe-inline` stays forbidden.

Unchanged and still frozen: `core_version` 1.0.0, rules, thresholds, metrics,
validation, outcomes, persistence and research data. As with 3.0.0, the
`core_manifest_hash` of snapshots created after this date differs.
