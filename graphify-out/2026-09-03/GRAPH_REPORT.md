## Database Safety Boundary

The central guard in `src/database/safety.py` enforces the following database routing before a test connection or schema initialization can occur:

| Caller | Permitted target | Enforcement |
|---|---|---|
| Runtime | Production DB | Normal runtime context only |
| Explicit production recovery | Production DB | Normal runtime context; exact recovery authorization remains separate |
| Tests | Test DB only | `TIM_DURABLE_TEST_DATABASE_URL`, loopback, test-marked DB name, exact fingerprint match |
| Integration tests | Test DB only | Same hard guard; missing explicit URL skips integration fixture or fails the suite runner |
| Test migrations / `initialize_schema()` | Test DB only | Guarded again immediately before schema execution |
| Migration tools | Explicit target only | Test context cannot target the production fingerprint |

Forbidden edge: **Test `initialize_schema()` → Production DB**. The connection guard and schema guard both reject it before network connection or DDL.
